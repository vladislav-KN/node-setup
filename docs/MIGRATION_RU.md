# Перенос существующей ноды с NGINX на Caddy

`migrate.sh` переносит **только прокси исходного установщика x1roko/node-setup**. Он не предназначен для панели, бота или произвольного NGINX-сервера. Нужны уже установленные Docker Compose и Python 3, действующий доверенный сертификат и рабочая нода.

## Сначала проверка

В каталоге этого форка на сервере ноды:

```bash
sudo bash migrate.sh --check
```

Без параметров скрипт тоже выполняет только проверку. Контейнеры, файлы, пакеты, firewall и задания продления не меняются. Выполняются чтение Docker/NGINX-конфигурации и обычные HTTPS GET-запросы к `/`. Тела ответов и секреты не печатаются.

Проверка распознаёт исходные пути `/opt/remnanode/nginx/docker-compose.yml`, `nginx.conf`, `fullchain.pem`, `privkey.key`, контейнер `remnanode-proxy` и его отдельный Compose-проект. Домен и пути XHTTP/gRPC берутся из NGINX. Должны работать сайт на `127.0.0.1:8080`, TLS через `/dev/shm/nginx.sock` с PROXY protocol и REALITY fallback на `127.0.0.1:443`.

Другие server-блоки, маршруты, директивы, монтирования или нестандартный Compose приводят к остановке. Конфигурации с другим REALITY target, несколькими доменами, ручным доступом только через публичный IP либо прямым TLS на NGINX требуют отдельной адаптации. Проверка NGINX читает текущие файлы и не доказывает, что они были последними загружены работающим процессом; дополнительно проверяются живые HTTPS-ответы и возможность запуска конфигурации для отката.

## Запуск переноса

```bash
sudo bash migrate.sh --apply --email you@example.com
```

Email также читается из `EMAIL` или `.env` рядом со скриптом. Ключ панели не запрашивается. По умолчанию Caddy получает сертификат через HTTP-01: DNS A/AAAA должны вести на эту ноду, порт 80 должен быть доступен снаружи. Для REALITY запись Cloudflare должна оставаться **DNS only**.

Для DNS-01 через Cloudflare:

```bash
sudo bash migrate.sh --apply --email you@example.com --tls-mode cloudflare
```

Токен запрашивается скрыто либо берётся из `CF_Token` в сохранённом `.env`. Нужны DNS Edit и Zone Read для нужной зоны. Модуль Cloudflare собирается до остановки NGINX. Токен остаётся только в закрытом Compose-файле; в журнал и Caddy JSON он не попадает.

Скрипт:

1. Сохраняет старые конфиги, сертификат, ключ, описание прокси и Compose с точным ID старого образа. Создаёт самостоятельный `rollback.sh`.
2. Загружает/собирает Caddy и проверяет его конфигурацию. Запускает тестовый Caddy на отдельном Unix-сокете с действующим сертификатом NGINX и проверяет сайт через TLS/PROXY protocol. NGINX продолжает обслуживать пользователей.
3. Проверяет, что контейнеры и исходные файлы не изменились во время подготовки. Останавливает и удаляет только контейнер старого прокси, затем запускает Caddy под тем же именем `remnanode-proxy`.
4. Ждёт доверенный сертификат Caddy и проверяет HTTPS через selfsteal-сокет и порт 443. При сбое выполняет откат на сохранённый образ NGINX. При успехе проверяет сохранение ID, времени запуска и сетей Remnanode и сайта-заглушки.

**Перерыв HTTPS возможен во время выдачи сертификата — до пяти минут перед откатом.** Уже установленные REALITY-сессии могут продолжать работу, но непрерывность VPN не гарантируется: новые подключения и трафик XHTTP/gRPC могут прерваться. Встроенные проверки не выполняют настоящий VPN-вход, поэтому после переноса проверьте обычное клиентское подключение.

## Совместимость и обслуживание

Активный Compose остаётся в `/opt/remnanode/nginx/docker-compose.yml`. Это JSON-документ, совместимый с Compose. Имя проекта и сервиса `nginx` сохранены, но внутри работает Caddy. Поэтому старые команды `docker compose ... restart` из заданий продления не поднимают NGINX обратно.

```bash
sudo docker compose -f /opt/remnanode/nginx/docker-compose.yml ps
sudo docker compose -f /opt/remnanode/nginx/docker-compose.yml logs --tail=50 nginx
```

Новые данные находятся в `/opt/remnanode/caddy-migration/<время-ID>/`: `caddy/config`, постоянное хранилище сертификатов `caddy/data` и закрытая папка `backup`. Сохраните этот каталог и не публикуйте его содержимое: там есть приватные ключи и, для DNS-режима, API-токен.

Скрипт не меняет Remnanode, его API/ключ, профиль Xray, Docker IP, конфигурацию сайта, firewall, DNS и существующий WARP. Уже установленный WARP не удаляется: от него могут зависеть действующие маршруты Xray. Новая установка через `install.sh` WARP не устанавливает.

Старые Certbot/acme.sh и их задания сохраняются: их сертификаты могут быть смонтированы непосредственно в Remnanode для других TLS-inbound. Они продолжают обновлять старые файлы и могут перезапускать ноду по прежним правилам. Caddy отдельно продлевает собственный сертификат. Этот скрипт не переносит управление сертификатами прямых TLS-inbound в Caddy и не отключает общие задания сертификатов других сервисов.

## Откат

Точный путь выводится **до переключения**, например:

```bash
sudo bash /opt/remnanode/caddy-migration/<время-ID>/backup/rollback.sh
```

Исходный репозиторий для отката не нужен: копии Python-скриптов уже сохранены в резервной копии. Откат проверяет старый образ и NGINX-конфигурацию, удаляет только Caddy своей миграции и воссоздаёт старый прокси. Remnanode и сайт не пересоздаются. Более новые файлы сертификатов не затираются старой копией.

При изменении Compose вручную или замене прокси другим контейнером автоматический откат откажется перезаписывать чужие изменения. При отключении питания или `kill -9` автоматический обработчик не сработает — используйте сохранённый `rollback.sh`. Не удаляйте старый NGINX-образ, пока нужен откат.

## Проверки проекта

Unit-тесты проверяют отказы до переключения, запуск отката на ошибках/прерывании и защиту от чужих изменений. Отдельный Linux Docker-тест реально переключает NGINX на Caddy, выполняет старую команду перезапуска и проверяет ручной и автоматический откат с сохранением контейнеров ноды и сайта. В этом стенде TLS использует временный сертификат, а TCP-реле представляет REALITY fallback; выдача публичного ACME-сертификата и настоящий VPN-вход требуют реальной ноды.
